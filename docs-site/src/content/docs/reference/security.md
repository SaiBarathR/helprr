---
title: Security notes
description: How Helprr protects accounts, credentials and connections.
---

- Use unique, long secrets and a private network or HTTPS reverse proxy. Do not expose Helprr directly to the public internet without understanding the security implications.
- Passwords are stored as per-user scrypt hashes. `APP_PASSWORD` seeds/resets only the bootstrap admin; it is not a universal login password.
- Local and Jellyfin credential requests are limited to 8 KiB; usernames are limited to 64 Unicode characters and passwords to 1,024 UTF-8 bytes. New and reset local passwords use the same byte ceiling. A separate 120-request-per-minute malformed-login backstop deliberately fails closed, so a sufficiently large malformed flood can briefly return 429 to otherwise valid sign-in attempts.
- Watching uses each member's own Jellyfin access token, not the Jellyfin admin API key, so a playback session is never more privileged than the member driving it. Those tokens are encrypted at rest and never returned by the API. A profile linked to a Jellyfin account can only connect that account; an unlinked profile links the account it signs in with, unless another profile already holds it. The connect endpoint shares the same rate limits as sign-in. If a Jellyfin administrator revokes a device, Helprr drops the token and asks that member to reconnect.
- Web Share Target requests accept only multipart or URL-encoded form bodies up to 16 KiB. Shared titles are limited to 256 Unicode characters, and shared text and URL fields are each limited to 2,048 UTF-8 bytes.
- Invite and password-reset links carry a random 256-bit token; Helprr stores only its SHA-256, so a database copy holds no working link. A link works once, until it expires (7 days for an invite, 24 hours for a reset), and only while the account is still pending (invite) or active (reset). The token sits after the `#` in the link, which browsers never send to a server, and the invite page removes it from the address bar and the tab's Back history as soon as it opens (the browser's own history list may still keep the full link). Every link that does not work gets the same answer. The invite page has its own rate limits, so a flood of bad links cannot lock anyone out of signing in, and each failed try is in the security log without the link. Using a reset link signs the person out everywhere.
- Two-step sign-in (Settings → Account) adds an authenticator code (TOTP, RFC 6238) after the password, for Jellyfin sign-in too. The secret is encrypted at rest like the Jellyfin tokens; the ten recovery codes are stored only as SHA-256 hashes and are shown once. A right password alone returns a five-minute, single-use token that is not a session; only that token plus a code makes one. Each code works once, and wrong codes go through the same rate limits as wrong passwords, which are not reset until the code passes. On top of that, an account gets 10 authenticator-code tries an hour and a pending token 5; recovery codes skip the hourly cap, so someone who knows only the password cannot lock the owner out of them. Turning it off yourself needs the password and a code. An admin can turn it off for someone else in Settings → Users, which signs them out everywhere. A password-reset link an admin made after it was turned on turns it off too, and never signs the browser in for an account that had it on: the person then signs in with the new password. An older link, or one you made for yourself, leaves it on. Turning it on can sign out your other devices. Settings backups never include the secret or the recovery codes, so an account a restore creates has it off (an existing account keeps its own).
- Personal API tokens (Settings → Sessions → API tokens) open only the read-only [status API](/helprr/status-api/): `GET /api/v1/summary` and `GET /api/v1/queue`. A token is `hlp_` and 256 random bits; Helprr stores only its SHA-256 and shows it once. It can read only what its owner ticked and can still see, is checked again on every request, and is refused anywhere else in Helprr, for any other method, and as a session. Mistyped tokens are rate-limited per address behind a trusted proxy, each token is rate-limited too, and no other website may call the API from a browser. Changing your password, an admin resetting it or disabling the account, and `HELPRR_ADMIN_PASSWORD_RESET` end every token the person has. Making and turning off tokens, and a token's first use from a new network (told apart only behind a trusted reverse proxy), are in the security log; tokens are never logged or included in settings backups. Revoking other sessions does not end tokens.
- Resetting the bootstrap password with `HELPRR_ADMIN_PASSWORD_RESET` signs the admin out everywhere, ends any reset link made for them, and turns off their two-step sign-in. It does that again at every start until the setting is removed.
- **Settings → Operation audit → Security** (admins only) lists sign-ins, failed sign-ins, and who added, changed, or removed a user, a permission, a session, a connection, or imported a settings backup, and who made, replaced, revoked or used an invite or password-reset link, and tries with a link that does not work. Two-step sign-in turned on or off, a recovery code used, and a wrong code (as a failed sign-in) are there too. It names the fields that changed, never their values, and keeps each record for 365 days. A failed sign-in keeps the username only when it belongs to an account; any other name is shortened to its first two characters and length, so a password typed into the username box is never stored. Repeats from one network in the same minute count on one row, and a switch hides failed sign-ins and failed link tries so they cannot bury other changes. Addresses are kept to their network (IPv4 /24, IPv6 /64) and only when Helprr runs behind a trusted proxy.
- Service credentials and custom headers are sensitive. Restrict administrator accounts and protect backups/log exports.
- Verify AI-generated changes before deploying them. Keep your service containers and this project up to date, and test upgrades against a backup.
- Found a vulnerability? Please report it privately — see [SECURITY.md](https://github.com/SaiBarathR/helprr/blob/main/SECURITY.md).
